# 移动端快速测试指南

## 🚀 快速测试步骤

### 1. 环境准备

#### 检查环境
```bash
# 检查 Node.js 版本
node --version  # 应该 >= 18

# 检查 React Native CLI
npx react-native --version

# 检查 Android SDK
echo $ANDROID_HOME  # Linux/Mac
echo %ANDROID_HOME%  # Windows
```

#### 安装依赖
```bash
cd mobile
npm install
```

### 2. 启动后端服务

```bash
# 回到项目根目录
cd ..

# 启动后端
npm run server

# 后端应该运行在 http://localhost:3000
```

### 3. 运行 Android 应用

#### 方法 1: 使用启动脚本（推荐）
```bash
cd mobile

# Windows
.\start.ps1

# Linux/Mac
./start.sh
```

#### 方法 2: 手动启动
```bash
cd mobile

# 启动 Metro
npm start

# 在另一个终端运行 Android
npm run android
```

### 4. 测试优化功能

#### 4.1 测试剪贴板监听

1. **启动监听**
   - 打开应用
   - 进入"设置"页面
   - 输入用户名和密码登录
   - 返回主页
   - 打开"剪切板监听"开关

2. **测试 URL 检测**
   - 在浏览器或其他应用复制一个文章链接
   - 例如：`https://mp.weixin.qq.com/s/xxxxx`
   - 应该收到通知："发现新链接"

3. **测试去重功能**
   - 再次复制相同的链接
   - 应该不会收到重复通知

4. **测试智能间隔**
   - 查看主页的"检查间隔"
   - 活跃时应该是 2 秒
   - 60秒不操作后应该变为 5 秒

#### 4.2 测试通知交互

1. **测试保存按钮**
   - 复制一个新链接
   - 收到通知后点击"保存"
   - 应该看到"正在保存"的提示
   - 稍后应该看到"保存成功"

2. **测试忽略按钮**
   - 复制一个新链接
   - 收到通知后点击"忽略"
   - 该链接应该从队列中删除

#### 4.3 测试同步功能

1. **测试自动同步**
   - 复制几个链接
   - 点击通知的"保存"按钮
   - 等待自动同步（最多5分钟）
   - 查看"同步统计"中的数据变化

2. **测试手动同步**
   - 复制几个链接
   - 点击主页的"立即同步"按钮
   - 应该看到同步进度指示器
   - 同步完成后应该看到成功提示

3. **测试批量同步**
   - 复制 10 个不同的链接
   - 点击"立即同步"
   - 观察同步速度（应该比之前快）

#### 4.4 测试用户界面

1. **测试加载状态**
   - 重启应用
   - 应该看到加载指示器
   - 加载完成后显示主页

2. **测试下拉刷新**
   - 在主页向下拉动
   - 应该看到刷新指示器
   - 统计数据应该更新

3. **测试自动刷新**
   - 保持应用打开
   - 观察统计数据每 10 秒自动更新

4. **测试详细统计**
   - 查看"监听统计"
     - 已处理链接数
     - 当前检查间隔
   - 查看"同步统计"
     - 上次同步时间
     - 累计同步数量

#### 4.5 测试性能监控

1. **查看性能报告**
   ```javascript
   // 在 Chrome DevTools 控制台执行
   performanceMonitor.printReport()
   ```

2. **查看性能指标**
   ```javascript
   const metrics = performanceMonitor.getMetrics()
   console.log('同步成功率:', metrics.syncSuccessRate)
   console.log('API错误率:', metrics.apiErrorRate)
   console.log('检查频率:', metrics.checksPerHour)
   ```

3. **查看最近错误**
   ```javascript
   const errors = performanceMonitor.getRecentErrors(5)
   console.log('最近错误:', errors)
   ```

#### 4.6 测试日志系统

1. **查看日志统计**
   ```javascript
   logger.printStats()
   ```

2. **查看错误日志**
   ```javascript
   const errors = logger.getErrors(10)
   console.log('错误日志:', errors)
   ```

3. **导出日志**
   ```javascript
   const logText = logger.exportLogs()
   console.log(logText)
   ```

### 5. 性能测试

#### 5.1 电量消耗测试

1. **准备**
   - 充满电
   - 记录当前电量
   - 启动监听

2. **测试**
   - 保持应用后台运行 1 小时
   - 记录电量消耗
   - 应该 < 5%

3. **对比**
   - 活跃使用（频繁复制链接）
   - 空闲使用（不复制链接）
   - 空闲时电量消耗应该更低

#### 5.2 内存占用测试

1. **查看内存**
   ```bash
   # Android
   adb shell dumpsys meminfo com.secondbrain
   ```

2. **长时间运行**
   - 运行 24 小时
   - 定期检查内存占用
   - 应该保持稳定，无内存泄漏

#### 5.3 同步性能测试

1. **单个同步**
   - 复制 1 个链接
   - 记录同步时间
   - 应该 < 5 秒

2. **批量同步**
   - 复制 10 个链接
   - 记录总同步时间
   - 应该 < 20 秒（平均 2 秒/个）

3. **并发效果**
   - 对比串行和并发同步
   - 并发应该快约 3 倍

### 6. 故障测试

#### 6.1 网络故障

1. **断网测试**
   - 关闭网络
   - 复制链接
   - 应该保存到本地队列
   - 恢复网络后自动同步

2. **弱网测试**
   - 使用慢速网络
   - 测试同步功能
   - 应该有重试机制

#### 6.2 后端故障

1. **后端停止**
   - 停止后端服务
   - 复制链接
   - 应该保存到本地队列
   - 显示同步失败

2. **后端恢复**
   - 重启后端服务
   - 应该自动重试同步
   - 最终同步成功

#### 6.3 应用重启

1. **保存状态**
   - 开启监听
   - 复制几个链接
   - 关闭应用

2. **恢复状态**
   - 重新打开应用
   - 监听状态应该保持
   - 待同步项目应该保留

### 8. 调试技巧

#### 8.1 查看日志

```bash
# 查看所有日志
adb logcat

# 过滤应用日志
adb logcat | grep -i "clipboard\|sync\|api"

# 查看 React Native 日志
adb logcat | grep -i "ReactNative"
```

#### 8.2 查看数据库

```bash
# 进入应用目录
adb shell
run-as com.secondbrain
cd databases

# 查看数据库
sqlite3 clipboard_queue.db
.tables
SELECT * FROM clipboard_queue;
.exit
```

#### 8.3 清除数据

```bash
# 清除应用数据
adb shell pm clear com.secondbrain

# 卸载应用
adb uninstall com.secondbrain
```

### 9. 常见问题

#### 问题 1: 监听不工作

**症状**: 复制链接后没有通知

**解决方案**:
1. 检查监听开关是否打开
2. 检查通知权限
3. 检查电池优化设置
4. 重启应用

#### 问题 2: 同步失败

**症状**: 内容一直显示"待同步"

**解决方案**:
1. 检查网络连接
2. 检查后端服务是否运行
3. 检查服务器地址配置
4. 查看错误日志

#### 问题 3: 应用被杀死

**症状**: 锁屏后监听停止

**解决方案**:
1. 将应用加入电池优化白名单
2. 允许应用自启动
3. 允许应用后台运行
