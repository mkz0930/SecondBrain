## 快速开始

### 第一步：启动服务

```bash
# Windows
.\scripts\start.ps1

# Linux/Mac
./scripts/start.sh
```

等待服务启动完成，看到以下信息表示成功：
```
Server is running on http://localhost:3000
Database initialized successfully
```

### 第二步：访问应用

打开浏览器访问：`http://localhost:5173`

### 第三步：进入研究助手

1. 登录系统（如果还没登录）
2. 点击右上角的 **"🔬 研究助手"** 按钮
3. 进入研究项目列表页

### 第四步：创建第一个项目

1. 点击 **"+ 新建研究项目"**
2. 填写项目信息：
   - **标题**：例如 "Vue 3 组件设计最佳实践"
   - **描述**：例如 "研究 Vue 3 中组件的设计模式、组合式API的使用、以及性能优化技巧"
3. 点击 **"创建"**

### 第五步：开始研究

1. 进入项目详情页
2. 点击 **"开始需求分析"**
3. AI会生成3-5个研究问题
4. 逐个回答问题
5. 按照提示完成后续步骤

## 功能详解

### 1. 项目管理

#### 创建项目

**位置**：研究项目列表页 → "+ 新建研究项目"

**必填字段**：
- **标题**：研究主题（建议10-30字）
- **描述**：研究目标和范围（可选，但建议填写）

**示例**：
```
标题: React Hooks 深入理解
描述: 掌握 React Hooks 的原理、使用场景和最佳实践，
      重点研究 useState、useEffect、useContext 等常用 Hooks
```

#### 编辑项目

**操作**：项目卡片 → 点击编辑按钮（✏️）

**可修改**：
- 标题
- 描述
- 状态（不建议手动修改）

#### 删除项目

**操作**：项目卡片 → 点击删除按钮（🗑️）

**注意**：
- 删除操作不可逆
- 会删除所有相关数据（问题、资料、关联）
- 建议先导出报告再删除

#### 状态筛选

**位置**：左侧边栏 → 状态筛选

**状态说明**：
- **草稿**：刚创建，还未开始分析
- **分析中**：正在进行需求分析或资料分析
- **研究中**：正在收集资料
- **已完成**：已生成报告

### 2. 需求分析

#### 开始分析

**位置**：项目详情页 → "开始需求分析"

**过程**：
1. 点击按钮
2. AI分析研究主题
3. 生成3-5个研究问题
4. 等待10-30秒

**AI生成的问题类型**：
- 范围确认：你想重点研究哪些方面？
- 目标明确：你的学习/应用目标是什么？
- 背景了解：你目前的了解程度如何？
- 需求细化：有哪些特殊需求或限制？

#### 回答问题

**位置**：项目详情页 → 问题下方的输入框

**操作**：
1. 在输入框中输入答案
2. 点击"提交回答"或按 `Ctrl+Enter`
3. AI可能生成后续问题
4. 继续回答直到所有问题完成

**回答技巧**：
- 尽量详细和具体
- 提供实际场景和需求
- 说明遇到的问题或困惑
- 明确期望的结果

**示例对话**：
```
AI: 你想重点研究哪些方面？
用户: 我想重点研究组合式API的使用和性能优化，
      特别是如何在大型项目中合理组织组件。

AI: 你目前对 Vue 3 的了解程度如何？
用户: 我已经使用 Vue 2 两年，刚开始学习 Vue 3，
      对基础语法有了解，但对组合式API还不太熟悉。

AI: 你的项目规模大概是怎样的？
用户: 中大型企业级应用，大约100+个组件，
      需要考虑代码复用和维护性。
```

### 3. 资料收集

#### 开始收集

**位置**：项目详情页 → "开始收集资料"

**过程**：
1. 点击按钮
2. 系统搜索本地内容库
3. 使用研究问题作为搜索关键词
4. AI评估每份资料的相关性
5. 等待30秒-2分钟

**搜索范围**：
- 本地内容库中的所有内容
- 标题和正文全文搜索
- 根据研究主题匹配

**相关度评分**：
- **0.8-1.0**：高度相关，直接回答研究问题
- **0.6-0.7**：相关，提供有用信息
- **0.4-0.5**：部分相关
- **0.0-0.3**：弱相关或不相关

#### 查看资料

**位置**：项目详情页 → "📚 资料" 按钮

**资料面板**：
- 按相关度排序
- 显示标题、来源、相关度
- 点击卡片查看详情

**资料详情**：
- 完整标题
- 资料类型（本地内容）
- 相关度评分
- 来源信息
- 完整内容

### 4. 资料分析

#### 开始分析

**位置**：项目详情页 → "开始分析资料"

**过程**：
1. 点击按钮
2. AI分析资料之间的关系
3. 识别相似主题
4. 发现引用关系
5. 找出互补信息
6. 等待1-2分钟

**关联类型**：
- **相似关系**：讨论相同或相似的主题
- **引用关系**：一份资料引用另一份
- **互补关系**：提供不同角度的信息

**关联强度**：
- **0.8-1.0**：强关联
- **0.5-0.7**：中等关联
- **0.2-0.4**：弱关联

### 5. 知识图谱

#### 查看图谱

**位置**：项目详情页 → "🕸️ 知识图谱" 按钮

**图谱元素**：
- **节点**：代表一份资料
  - 大小：相关度越高，节点越大
  - 颜色：蓝色=本地内容，紫色=网络资源
- **边**：代表资料之间的关联
  - 粗细：关联强度
  - 样式：实线=相似，虚线=引用，点线=互补

#### 交互操作

**拖拽节点**：
- 鼠标按住节点
- 拖动到新位置
- 释放鼠标

**查看信息**：
- 鼠标悬停在节点上
- 显示资料标题、类型、相关度
- 显示内容预览

**缩放控制**：
- 点击 ➕ 放大
- 点击 ➖ 缩小
- 点击 🔄 重置视图

### 6. 报告生成

#### 生成报告

**位置**：项目详情页 → "📄 生成报告"

**过程**：
1. 点击按钮
2. AI分析所有资料
3. 生成结构化报告
4. 等待1-2分钟

**报告结构**：
```markdown
# 研究报告

## 研究概述
- 研究主题
- 研究目标
- 研究范围

## 核心发现
- 针对每个研究问题的发现
- 关键信息总结
- 重要观点提炼

## 关键洞察
- 深层次的理解
- 最佳实践建议
- 注意事项

## 参考资料
- 引用的资料列表
- 来源信息
```

#### 使用报告

**查看报告**：
- 报告以Markdown格式显示
- 支持标题、列表、代码块等格式
- 可滚动查看完整内容

**复制报告**：
- 点击"复制报告"按钮
- 粘贴到其他应用（如Word、Notion）
- 保留Markdown格式

**保存报告**：
- 复制到文本编辑器
- 保存为 `.md` 文件
- 或使用浏览器打印功能保存为PDF

## 使用技巧

### 1. 提高资料收集效果

**技巧1：积累本地内容**
- 在使用研究助手之前
- 先在"外挂大脑"中添加相关内容
- 保存相关文章、笔记、文档

**技巧2：使用明确的标题**
- 内容标题要清晰明确
- 包含关键词
- 便于搜索匹配

**技巧3：添加摘要**
- 为内容添加摘要
- 提高搜索准确度
- 加快相关性评估

### 2. 优化研究问题回答

**技巧1：提供具体信息**
```
❌ 不好的回答: "想学习Vue"
✅ 好的回答: "想学习Vue 3的组合式API，
              重点是如何在大型项目中使用，
              目标是应用到公司的企业级项目中"
```

**技巧2：说明实际场景**
```
❌ 不好的回答: "想了解性能优化"
✅ 好的回答: "我们的项目有100+个组件，
              首屏加载较慢，想了解如何优化
              组件加载和渲染性能"
```

**技巧3：明确期望结果**
```
❌ 不好的回答: "想学习"
✅ 好的回答: "希望能够独立设计和实现
              可复用的组件，并能够指导
              团队成员使用最佳实践"
```

### 3. 充分利用知识图谱

**技巧1：识别核心资料**
- 节点越大，相关度越高
- 优先阅读大节点对应的资料

**技巧2：发现知识关联**
- 关注连接较多的节点
- 这些资料可能是核心概念

**技巧3：探索知识网络**
- 从一个节点出发
- 沿着边探索相关资料
- 建立系统化的理解

### 4. 提升报告质量

**技巧1：完整回答问题**
- 认真回答所有AI问题
- 提供详细信息
- 报告会更有针对性

**技巧2：收集足够资料**
- 确保本地有相关内容
- 资料越多，报告越全面
- 建议至少10份相关资料

**技巧3：多次迭代**
- 第一次报告不满意
- 可以创建新项目
- 调整研究主题和问题回答

## 问题排查

### 问题1：AI分析失败

**现象**：
- 点击"开始需求分析"后报错
- 显示"AI Service unavailable"

**原因**：
1. API Key未配置或无效
2. 网络连接问题
3. API配额用完

**解决方法**：
```bash
# 1. 检查环境变量
cat .env | grep GOOGLE_API_KEY

# 2. 查看后端日志
tail -f logs/combined-*.log

# 3. 测试网络连接
curl https://generativelanguage.googleapis.com

# 4. 等待一段时间后重试
```

### 问题2：搜索不到资料

**现象**：
- 点击"开始收集资料"
- 显示"找到0份资料"

**原因**：
1. 本地内容库为空
2. 研究主题太具体
3. 关键词不匹配

**解决方法**：
1. 先添加相关内容到"外挂大脑"
2. 使用更通用的研究主题
3. 调整问题回答，提供更多关键词

### 问题3：知识图谱显示异常

**现象**：
- 图谱为空或显示不正常
- 节点重叠或布局混乱

**原因**：
1. 未完成"分析资料"步骤
2. 资料太少（<3份）
3. 浏览器兼容性问题

**解决方法**：
1. 确保完成"分析资料"步骤
2. 收集更多资料（建议10+份）
3. 刷新页面重新加载
4. 使用Chrome或Edge浏览器

### 问题4：报告生成失败

**现象**：
- 点击"生成报告"后报错
- 报告内容为空

**原因**：
1. 资料太少
2. AI调用超时
3. 网络问题

**解决方法**：
1. 确保至少有5份相关资料
2. 等待更长时间（最多2分钟）
3. 检查网络连接
4. 查看后端日志

## 最佳实践

### 1. 研究前准备

**准备清单**：
- [ ] 明确研究目标
- [ ] 积累相关内容（建议10+份）
- [ ] 准备好问题的答案
- [ ] 确保网络连接稳定
- [ ] 预留足够时间（15-30分钟）

### 2. 项目命名规范

**好的命名**：
```
✅ "Vue 3 组件设计最佳实践"
✅ "React Hooks 深入理解"
✅ "前端性能优化方法总结"
```

**不好的命名**：
```
❌ "学习"
❌ "研究1"
❌ "测试项目"
```

### 3. 描述编写建议

**好的描述**：
```
研究 Vue 3 中组件的设计模式、组合式API的使用、
以及性能优化技巧。重点关注大型项目中的组件组织
和代码复用，目标是应用到实际项目中。
```

**包含要素**：
- 研究范围
- 重点内容
- 应用场景
- 期望目标

### 4. 问题回答策略

**STAR原则**：
- **S**ituation：说明情况和背景
- **T**ask：明确任务和目标
- **A**ction：描述具体需求
- **R**esult：期望的结果

**示例**：
```
情况：我们团队正在开发一个大型企业级应用
任务：需要选择合适的状态管理方案
需求：支持TypeScript，易于维护，性能好
结果：希望能够做出明智的技术选型决策
```

### 5. 资料管理建议

**分类管理**：
- 按技术栈分类
- 按主题分类
- 添加清晰的标签

**定期整理**：
- 每周整理一次
- 删除过时内容
- 更新重要资料

**质量优先**：
- 优质内容 > 数量
- 官方文档优先
- 实践经验重要

### 6. 报告使用建议

**立即保存**：
- 生成后立即复制
- 保存到本地文件
- 或添加到"外挂大脑"

**二次加工**：
- 报告是基础
- 可以进一步编辑
- 添加个人理解

**持续更新**：
- 定期回顾报告
- 补充新的理解
- 更新过时信息
