## 系统概述

Second Brain 采用经典的**前后端分离架构**：

```
┌─────────────────┐      HTTP/REST      ┌─────────────────┐
│                 │ ◄─────────────────► │                 │
│   Vue 3 SPA     │                      │   Express API   │
│  (Port 5173)    │                      │   (Port 3000)   │
│                 │                      │                 │
└─────────────────┘                      └────────┬────────┘
                                                  │
                                                  ▼
                                         ┌─────────────────┐
                                         │                 │
                                         │  SQLite Database│
                                         │   (brain.db)    │
                                         │                 │
                                         └─────────────────┘
```

### 设计原则

| 原则 | 说明 |
|------|------|
| 关注点分离 | 前后端职责明确，通过 REST API 通信 |
| 单一职责 | 每个模块/服务专注于单一功能 |
  | 可测试性 | 业务逻辑与路由分离，便于单元测试 |
| 可扩展性 | 模块化设计，便于添加新功能 |

## 架构设计

### 三层架构

后端采用经典的三层架构模式：

```
┌─────────────────────────────────────────────────────────┐
│                      Presentation Layer                  │
│                    (Routes - API Endpoints)              │
│  - 请求验证  - 参数解析  - 响应格式化                     │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│                       Business Logic Layer               │
│                      (Services - 业务逻辑)                │
│  - AI 分析  - 同步逻辑  - 数据转换  - 冲突解决            │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│                      Data Access Layer                   │
│                     (Models - 数据访问)                   │
│  - SQL 执行  - 连接管理  - 事务处理                       │
└─────────────────────────────────────────────────────────┘
```

### 目录结构映射

```
server/
├── routes/          # 表现层 - API 端点定义
├── services/        # 业务逻辑层 - 核心业务逻辑
├── models/          # 数据访问层 - 数据库操作
└── middleware/      # 横切关注点 - 认证、日志等
```

## 性能考虑

### 前端优化

| 策略 | 实现 | 效果 |
|------|------|------|
| 虚拟滚动 | 大列表分页加载 | 减少渲染压力 |
| 按需加载 | 路由懒加载 | 减少初始包大小 |
| 防抖搜索 | 搜索输入防抖 | 减少 API 调用 |
| 本地缓存 | Pinia 状态缓存 | 减少重复请求 |

### 后端优化

| 策略 | 实现 | 效果 |
|------|------|------|
| 索引优化 | 常用查询字段建索引 | 加快查询速度 |
| 增量同步 | 只同步变更内容 | 减少数据传输 |
| 连接池 | SQLite 连接复用 | 减少连接开销 |
| 异步处��� | AI 分析异步执行 | 不阻塞主线程 |
